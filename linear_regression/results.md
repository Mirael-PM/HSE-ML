# Отчёт по домашнему заданию

## Что было сделано

1. **EDA** (часть 1 ноутбука):
   - проверены дубликаты и пропуски, удалены 1093 повторяющиеся строки по фичам без таргета;
   - текстовые поля `mileage`, `engine`, `max_power` приведены к численному виду;
   - `torque` разобран на величину (Nm) и `max_torque_rpm`;
   - пропуски заполнены медианами **train**, медианы переиспользуются на test/inference;
   - визуализации: pairplot, тепловые карты Pearson / Spearman / phik, боксплоты.

2. **Препроцессинг и feature engineering** (части 2–4):
   - категоризация `engine` (по объёму) и `seats` (по числу мест);
   - инженерные фичи `car_age`, `car_age_sq`, `power_per_cc`, `usage_per_year`, `wear_class`
     (квантильное разбиение `usage_per_year` по q20/q80 train);
   - бренд берётся как первое слово из `name`;
   - `OneHotEncoder(drop='first', handle_unknown='ignore')` по 8 категориальным признакам;
   - log-преобразование таргета `log1p(selling_price)`.

3. **Модели**:
   - `LinearRegression`, `Lasso` + `GridSearchCV`, ручной L0-перебор, `Ridge` + OHE,
     `Ridge` + полный FE — последняя выбрана как финальная.

4. **Streamlit-приложение** (это репо): три раздела — EDA, инференс (ручной ввод + CSV),
   веса модели; обученная модель сохранена в `model.pkl`.

## Полученные результаты

| Этап | Модель | Test R² | Комментарий |
|---|---|---|---|
| Часть 2 | LinearRegression, только числовые | ~0.59 | базовый бенчмарк |
| Часть 2 | Lasso + GridSearchCV | ~0.59 | без качественного прироста — числовых фич мало |
| Часть 3 | Ridge + OHE категориальных | ~0.65 | добавление бренда и `fuel`/`transmission` даёт +0.06 |
| **Часть 4** | **Ridge + FE + log-таргет** | **0.93** | финальная модель |

Точные финальные метрики (зашиты в `model.pkl → metrics`):

- `best_alpha ≈ 1e-6` (Ridge),
- `CV R² (log) ≈ 0.88`,
- `Train R² ≈ 0.91`,
- **`Test R² ≈ 0.93`**,
- `Test MSE ≈ 4.0e+10`.

## Что дало наибольший прирост качества

1. **Log-преобразование таргета** — цена распределена сильно скошенно (тяжёлый
   правый хвост), линейная модель в исходном масштабе плохо работает на дорогих
   объектах. После `log1p` Ridge выходит на R²≈0.93.
2. **OHE бренда** (`name → первое слово`): на одном «Maruti» vs «BMW» уже сильно
   разносятся ценовые сегменты.
3. **`car_age` + `car_age_sq`**: позволяют уловить нелинейный износ.
4. **`power_per_cc`**: одно число вместо двух коррелированных
   (`max_power`, `engine`) ослабляет мультиколлинеарность.

## Что не получилось

- Лассо на чисто числовых не уехал заметно дальше OLS, потому что доля
  «безполезных» признаков мала, штраф L1 убирает шум, но не добавляет
  информации.
- Ручной L0-перебор (часть 2, задание 18) даёт лишь маргинальный прирост — это
  ожидаемо: на 8 фичах подмножества почти не отличаются по предсказательной
  силе.
- Полностью отделить эффект бренда от объёма двигателя/мощности не удалось:
  дорогие бренды (BMW, Mercedes) систематически дают и больше cc, и больше bhp,
  поэтому коэффициенты OHE по бренду и `max_power` тянут «друг друга».

## Оценка сервиса

- **Удобство использования.** Sidebar даёт прямой переход между разделами, в
  каждом из трёх блоков логика собрана компактно. Ручной ввод собран в три
  колонки — заполнить машину можно за 30 секунд. Загрузка CSV возвращает таблицу
  с предсказаниями и кнопку «Скачать predictions.csv».
- **Что получилось хорошо.** Интерактивная гистограмма цены (с переключателем
  log-шкалы), скаттер `year × selling_price` с цветом по `fuel`, бар-чарт
  коэффициентов с диапазоном слайдером для топ-N — все они «отвечают на
  вопросы» и не требуют объяснений.
- **Что менее удачно.** Heatmap корреляций намеренно показывается только по
  трём «надёжно числовым» полям — после очистки `mileage/engine/max_power` в
  тренировочном CSV они всё ещё хранятся как строки, и тащить очистку прямо в
  EDA-вкладку было бы перегрузом. Возможное улучшение — отдельная вкладка
  «после препроцессинга» с расширенной корреляционной матрицей.
- **Ограничения и проблемы.**
  1. Для неизвестных брендов и категорий OHE возвращает нули — модель скатывается
     к «среднему» бренду; в форме это смягчено за счёт `selectbox` со списком
     известных значений.
  2. Логирование/мониторинг отсутствует, ошибки на CSV ловятся try/except, но
     детальной диагностики не выводится.
  3. Модель линейная — для дорогих люкс-сегментов абсолютная ошибка остаётся
     большой даже при хорошем R².
- **Что улучшить в следующей итерации.**
  - Добавить кэширование инференса по хешу входных данных.
  - Раскрасить точки в scatter цветом по предсказанной цене после загрузки CSV.
  - Сравнительный режим: пользователь меняет один признак, и видно, как меняется
    предсказание (partial-dependence «на лету»).
  - Подключить градиентный бустинг как опциональную модель и сравнивать в UI.
